# CopyX 架构设计

## 目标与平台

独立桌面软件，目标为 macOS 14+ Apple Silicon、Windows 10/11 x64。交付分为构建产物与平台实机验证两个状态。

## Tauri 2 与 Rust 桌面宿主

0.2.0 增加独立 Tauri 构建入口。macOS 使用系统 WKWebView，Windows 使用 WebView2。React、Monaco、工作台和设置页面复用同一份构建产物。Electron 0.1.x 的宿主与构建仍可用于对照及回退。

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 界面桥接 | src/tauri-desktop.ts、src/desktop.ts | 维持固定 Desktop 接口，封装 IPC 响应和事件订阅 |
| Tauri 宿主 | src-tauri/src/main.rs、capabilities/main.json | 单实例、托盘、菜单与窗口，限制本机主窗口访问固定命令及事件 |
| 命令与任务调度 | src-tauri/src/desktop.rs | 请求分发、任务互斥与取消、脚本生效凭据、配置与系统注册回退 |
| 快捷键与系统取文 | src-tauri/src/shortcuts.rs、native.rs、electron/native/ | 当前系统键位注册、探测和暂停；松键后复用 Swift 与 PowerShell 助手 |
| 配置、密钥与提示词历史 | src-tauri/src/store.rs、contract.rs | 版本兼容、首次迁移、加密和原子保存、历史与收藏 |
| 脚本执行和静态检查 | src-tauri/src/script.rs、script-validator.js | QuickJS 子进程、测试、指纹、Acorn 检查 |
| 模型请求与会话 | src-tauri/src/ai.rs、conversation.rs | Chat Completions、超时与取消、方案确认、会话与测试结果存储 |
| 处理分享与导入 | src-tauri/src/share.rs | 原生文件窗口、版本 1 字段白名单和可选测试集 |

React 通过本机主窗口调用 Rust。WebView 拒绝外部导航与新窗口，界面只能订阅应用事件和请求受限命令。模型 HTTP、磁盘、系统快捷键、剪贴板均由 Rust 或取文助手访问，系统能力不注入用户脚本。脚本执行与静态检查使用本应用二进制的独立工作进程，输入输出只经管道，传入的进程环境为空。每个任务新建 QuickJS 上下文，沿用 32 MB、2 秒限制，取消或外层超时会终止子进程。处理、脚本测试和脚本会话使用独立请求标识，取消可在任务准备阶段中断，先到的取消按标识短暂保留。覆盖或删除操作等待 Rust 原生确认结果后再修改界面状态。首轮快捷键注册在界面读取配置时完成，失败信息随配置返回。

Tauri 使用独立应用标识 `com.textworkbench.desktop.tauri`。首次启动从旧版「文本工坊」数据目录复制 `config.json`、`master.key`、`script-conversations.json` 到新应用数据目录下的 `data`，完整副本一次提交。后续两端分别保存，各自拥有独立的状态和辅助功能授权。继续使用同一套密文、分享文件、脚本指纹和会话格式；本机加密沿用 AES-256-GCM。迁移时应先退出旧版，避免两套宿主同时占用快捷键。

以下链路描述两套宿主共享的行为。表中的 Electron 文件以及 Worker、AbortController 等实现细节属于 0.1.x 对照版本。

## 取文与处理数据流

专用快捷键 → 等待用户释放组合键 → 原应用模拟复制 → 剪贴板序号确认更新 → 读取纯文本 → 打开窗口 → 传入原文与方案编号 → 处理策略 → 返回结果 → 字符对照 → 人工修改 → 两侧各自复制。

窗口获得焦点前完成取文。复制失败、非文本、权限缺失、输入超限均明确失败，不回退旧剪贴板。通过系统复制获取选文仍受目标软件复制行为约束，不能保证受保护应用或并发剪贴板写入场景。

每条 JavaScript 指令可配置 `directPaste`，缺省为 false，分享文件不包含此本机设置。全局快捷键命中已开启直接粘贴、已启用且有验证快照的指令时，桌面宿主在现有互斥内运行同一脚本执行器。原生助手保留取文时的焦点和选区快照，通过子进程标准输入输出接收结果，在写入前重新核对原窗口、控件、选区和原文。macOS 定向写入支持替换的辅助功能文本控件，Windows 定向写入可核对的原生 Edit 控件。无法确认时以原文和已计算结果打开核对页。脚本异常保留原文并显示错误。手动执行和 AI 指令沿用核对流程，正文和结果不写入文件。

左侧与模型输入保留原始字符串。程序更新结果不会被误当成人工编辑。右侧人工编辑后，以编辑器当前内容复制。混合换行在人工编辑时可能按编辑器的文档换行格式统一；未经编辑的原文及结果保持原始字符串。

重跑以最初原文输入，覆盖人工结果前确认。取消请求由主进程 AbortController 中止，处理完成前检查取消状态。AI 响应及大小验证通过后进入历史保存阶段，此时本次处理已完成。执行期间右侧只读，防止结果覆盖刚输入的文字。

## 快捷键配置流程

界面只显示当前系统的快捷键。录入组合键会同时更新键位和兼容字段 enabled，清空当前键位后保存即释放此平台的注册。JavaScript 使用各自的 shortcutMac/shortcutWin 和 enabled，AI 共用配置根部的 aiShortcut，包含相同三个字段。旧配置中 enabled 为 false 的键位显示为未设置，继续保持未注册，重新录入时清除旧的另一平台未启用键位。旧 AI 配置首次加载时，每个平台取首个已启用并填写的旧键位。原有 AI 处理与模型配置继续用于手动执行。注册与冲突检查共用 shortcutBindings，仅投影一个 AI 目标和所有 JavaScript 处理。

录入 → 规范化修饰键顺序与别名 → 检查其他已启用自定义处理的重复 → 检查常用系统组合 → 临时向系统注册探测 → 即时显示结果。探测只注销自己的临时键位，不注销已有绑定。无法注册时明确提示，不承诺能枚举所有应用内部快捷键或系统保留组合。

录入期间暂停 CopyX 自身的全局快捷键，防止旧绑定抢走输入；输入框失焦、窗口失焦或控件卸载时恢复。新增固定 IPC 操作为 shortcut:check、shortcut:record-start、shortcut:record-end，仍仅允许主窗口主框架调用。过时的界面检测结果不会覆盖新输入的结果。

保存再次检查并先申请全部新增键位，全部成功后才释放不再使用的旧键位；申请失败只撤回新增项，保留原有绑定。持久化失败时恢复原配置的键位设置。

## AI 配置与接口

用户配置服务地址、API Key 与准确模型名称。地址支持基础路径及完整 /chat/completions；软件不猜测服务商版本路径，不自动追加 /v1。请求非流式，不额外强加 temperature 或输出上限，优先兼容不同服务商。工作台 AI 转换在 system 消息拼接共用输出约定及用户指令，user 消息仍为原文。两种宿主只接受单个结果对象，text 字段逐字符返回，unchanged 标记直接复用原文。兼容完整单层 JSON 围栏。文本回复格式错误时，在原消息中补充格式要求并自动再请求一次，不附带上次错误回复。两次共用 60 秒时限和同一取消信号；只有最终通过解析与输出检查的结果进入提示词历史。

连接测试使用短测试文本，脚本生成沿用多轮会话流程。两者以及文本转换的 HTTP 错误、请求超时、输出截断和取消均不触发自动重试。禁止 HTTP 重定向以避免密钥发给另一个地址。接口错误只显示状态与操作建议，不回显上游响应正文和密钥。输入最大 1 MB，模型响应 JSON 最大 8 MB，最终结果最大 2 MB。

## AI 提示词历史与执行

工作台的提示词胶囊与历史抽屉共用同一历史状态及排序规则。胶囊只取前四条，点击写入当前提示词草稿。实际执行成功后由既有历史链路更新最近记录及共享快捷键默认提示词。

工作台手动执行 → process:run-prompt → 校验提示词与模型配置 → 运行现有 AI 文本处理 → 验证取消状态与输出长度 → 写入提示词历史 → 返回结果及历史。相同文本按原字符串去重，成功记录移到首位，保留收藏状态。只有这条文本处理链路自动记录，模型连接测试和 JS 生成不参与历史。

共享快捷键 → 在主进程读取最近成功记录与对应 AI 处理 → 获取选文 → 界面确认覆盖人工结果 → process:run-prompt 通过历史记录编号再次校验目标 → 复用上次成功的提示词及模型。记录对应处理或模型关联发生变化时，先显示原文和手动执行提示。历史为空同样提示首次执行。删除当前记录后选择数组中的下一条记录。收藏和列表顺序不参与执行目标解析。

ConfigStore 在 config.json 的 promptHistory 保存提示词、收藏标识及最近一次成功执行的提示词快照和处理/模型引用。提示词编辑更新列表文字，成功快照在新版本成功执行时才替换。维护使用固定 IPC prompt-history:update，与处理、取文、配置保存互斥。普通配置保存始终保留主进程现有历史，避免旧草稿回写。历史与其他配置使用同一原子替换操作，最多 500 条、总计 8 MB，满额或写入失败时仍返回处理结果并提示保存失败。普通工作台输入和结果不进入配置。

## AI 辅助脚本生成与测试校验

自定义处理的 JavaScript 编辑区 → 用户发送处理要求/补充意见 → script:discuss 固定 IPC → 会话服务用独立 QuickJS 评估器重跑当前脚本测试 → 将已有脚本、测试输入、预期、实际结果与对话发给用户选择的模型 → 返回处理方案 → 本地保存会话。每轮都会刷新测试报告；上下文未变时只追加最新报告，完整脚本和测试集不重复附加。讨论用评估器与生效凭据分离，避免讨论清除可用预览的通过记录。

用户可继续补充，最新方案替换旧方案编号。用户明确点击“确认方案并生成脚本” → script:generate 校验会话、方案编号、模型与当前脚本/测试指纹 → 多轮消息加确认指令，生成代码 → 静态检查 → 原有本地测试 → 返回预览和结果，保存对话反馈。失败结果进入下一轮上下文，不自动再请求模型。不处理工作台正文，不自动保存脚本草稿或打开工作台。

草稿保存写入 scheme.script 与 scheme.testCases，不覆盖 scheme.activeScript。至少 1 例且全部通过后，script:activate 核对已保存草稿与后台凭据，持久化新的 activeScript 快照，继续留在设置页。快照包含脚本、对应测试集、指纹及通过时间。配置保存忽略客户端提交的 activeScript，始终保留后台版本。失败、取消和空测试集都不能产生通过凭据；修改代码或测试集后旧指纹不再匹配。

专用快捷键或工作台手动执行 → 读取 activeScript 生效快照 → QuickJS 本地处理。此链路不读取草稿、不调用生成模型。新处理没有生效快照时不可执行，且不注册后台快捷键；生效时重新检查快捷键冲突。旧处理保存失败草稿后，原版本仍继续运行。工作台及 AI 提示词命令类型不挂载脚本生成组件。

讨论时明确向所选模型发送当前脚本、测试输入/预期/实际结果以及当前对话，替代原先单次生成时可选附带样例的交互；界面列明发送范围。不自动读取工作台正文，也不自动发送模型密钥或连接设置。每轮都使用真实 user/assistant 消息历史，模型只在用户发送或确认时调用；空缺模型设置先提示配置。模型提供商或密钥发生变化后，旧方案不可继续生成；更换模型在界面确认后开始新对话，不把旧历史转发给另一模型。

会话位于 userData/script-conversations.json，格式版本为 1，每个处理保留最新会话；保存发送的要求、模型方案、当前上下文快照、生成代码及测试反馈。用户选择允许本地保存并重启继续，未发送的输入框内容不属于已保存对话。新对话首轮成功后替换该处理原历史；生成失败、取消和断电不能覆盖完整原文件。仓储采用临时文件 0600、目录 0700 和原子替换，整体最大 16 MB，串行写入避免丢更新。格式损坏保留原文件并进入只读保护；业务结构不完整时不向渲染层返回对象，显示可恢复提示。保存失败仍保留本轮内存结果，但明确提示未持久化。

后台拥有会话和方案状态，客户端不提交伪造的 assistant 历史。方案只对对应处理、模型配置、代码和测试集快照有效，未发送补充意见时界面禁止跳过它直接生成；更改上下文后须讨论新方案。恢复对话不会恢复内存测试通过凭据，历史报告只供参考；恢复会话草稿需用户确认且不改生效版本。已有工作台正文仍不落盘，用户主动维护的测试与会话是明确的本地配置数据。

脚本生成的模型请求单独使用 5 分钟等待上限，覆盖响应读取并可随时取消；普通 AI 文本处理仍为 60 秒，模型连接测试仍为 15 秒。本地单例/整套脚本测试时限不随模型等待时间变化。

生成使用同步单参数 function transform(text) 契约。Acorn 按 ECMAScript 2022 script 模式检查语法和入口；接受纯代码或完整 JavaScript 代码围栏，生成代码最多 64 KB、要求最多 8 KB。静态检查不执行顶层语句，测试通过也不保证测试集以外输入正确。实际运行继续受 QuickJS 的内存、超时和字符串返回类型限制，禁止外部依赖、异步、文件或网络访问。

讨论、生成和测试共用主进程任务互斥。script:generate-cancel 携带请求标识，取消同一任务的讨论/生成模型请求或自动测试；script:conversation-get 仅返回可显示的本地会话。手动测试使用 script:test / script:test-cancel，生效使用 script:activate，均沿用主窗口主框架授权和固定桥接。组件卸载取消匹配请求，迟到响应不能应用到其他处理。生成后原稿发生人工修改时，应用前再次确认覆盖。

会话最多 12 轮讨论，每次用户要求 8 KB，方案/代码回复最多 64 KB，多轮请求消息总体最多 4 MB；超限提示重新开始，不静默截断。渲染层将模型方案和用户消息作为 Markdown 安全渲染，不执行原始 HTML。主进程最多缓存 10 个最近会话，更多会话从仓储恢复。

后台通过凭据按处理编号隔离，绑定脚本和用例全部字段的 SHA-256 指纹；客户端报告或状态不能作为生效依据。最多 50 例，单输入/预期最多 64 KB，总样例文本最多 512 KB，每例 2 秒、整套 15 秒；单例测试实际输出最多 64 KB，超限记失败并不回传巨量文本。失败不自动重试模型。

配置版本升级到 schemaVersion=2。加载旧配置时仅将当时的脚本迁移成 status=legacy 生效快照，标注尚未验证；以后保存草稿不会再次产生旧版豁免。原有大于 64 KB 的旧脚本可继续原样保存和执行，新改代码按新限制处理。重启保留生效快照和草稿，内存测试凭据不跨重启；未生效草稿需重新测试。

## 对话抽屉与消息展示

ScriptGenerator 保留会话、输入、预览及请求状态，将展示委托给 RightDrawer 和 MarkdownMessage，避免容器依赖后端协议。RightDrawer 使用 Portal 挂到 body，以原生 dialog.showModal 提供背景不可交互和焦点限制；关闭调用容器回调，由原生 dialog.close 恢复入口焦点。支持 Esc、遮罩和按钮关闭，遵循减少动态效果偏好。抽屉内部按需挂载，关闭不卸载 ScriptGenerator，不触发其取消逻辑；自身请求未结束时仍允许重新打开。外部测试忙状态仍禁用入口。应用预览后收起抽屉，回到草稿编辑。

MarkdownMessage 使用 react-markdown 10.1.0 和 remark-gfm 4.0.1，以组件映射展示 CommonMark 和 GFM；不启用原始 HTML 解析，skipHtml 忽略嵌入标签，默认 URL 转换限制危险协议。远程图片仅显示说明，不自动访问外部地址。代码块与表格各自滚动，不扩展窗口。原有渲染层网络、外部导航和新窗口限制继续有效。消息仓储、IPC 以及模型请求仍传递原始字符串，渲染不回写历史内容，不改变方案确认和测试凭据。参考：[react-markdown 官方文档](https://github.com/remarkjs/react-markdown)、[remark-gfm 官方文档](https://github.com/remarkjs/remark-gfm)。

## 自定义处理分享与导入

编辑中的处理 → scheme:export 固定 IPC → 主进程验证并按字段白名单生成 `.copyx.json` → 原生保存窗口 → 同目录临时文件写入并原子重命名。文件格式为 `copyx.custom-processing` 版本 1，最多 8 MB。脚本内容及用例沿用 64 KB 脚本、50 条用例及用例文本的原有校验。测试集默认空，用户在分享窗口主动勾选后纳入输入和预期输出。AI 只导出初始提示词。文件操作沿用主进程互斥，阻止处理请求或配置保存并发修改。

原生打开窗口 → scheme:import 固定 IPC → 有界读取和 UTF-8、JSON、格式版本校验 → 仅提取可移植字段 → 生成新 UUID 和关闭的空键位 → 回传渲染层作为新增草稿。界面处理同名后缀，普通保存流程负责持久化。源文件中的模型、API Key、处理标识、快捷键、生效快照和历史字段均不参与导入。测试快照由接收端重新生成，未生效的脚本不能运行。

配置允许 AI 草稿暂时缺少模型引用，非空引用仍需指向已配置的模型。手动执行要求先绑定模型。快捷键录入依旧检查草稿键位，实际注册只在至少一个 AI 处理绑定模型时投影共享 AI 目标。导入草稿不配置或改写本机共享键位。

## 存储与权限

配置位于 Electron userData/config.json，使用临时文件加原子重命名。保存前完成结构、引用与快捷键注册验证，失败恢复旧快捷键。

API Key 使用 AES-256-GCM 加密，将带版本前缀的密文写入 config.json。随机 32 字节主密钥单独保存于同目录 master.key，每次加密生成独立 12 字节 nonce，并保存 16 字节认证标签；模型标识作为附加认证数据，避免密文在不同模型间直接替换。主进程向 ConfigStore 注入 LocalKeyVault，渲染进程只获得 hasKey/needsKeyUpdate 状态，不获得密文、主密钥或已保存的 API Key。

首次明确保存 API Key 才创建主密钥：临时文件写入完成后通过原子链接发布，已存在的主密钥绝不覆盖，支持并发首次保存。新建主密钥文件权限为 0600，目录创建权限为 0700；Windows 仍由用户目录权限控制访问。读取时拒绝损坏文件，缺失主密钥不会在解密过程中自动重建。密文篡改或错误主密钥会导致认证失败，不退回明文保存。

密钥管理不调用系统钥匙串、DPAPI 或 Touch ID，也不要求用户每次启动重新填写 API Key。主密钥与密文都是本地文件，因此这一方案主要防止配置文件单独泄露明文；获取两个文件的人仍可解密，不提供系统钥匙串级别的访问隔离。备份或迁移需要同时保护两个文件。

旧版系统加密密文原样保留，不自动访问旧系统凭据或删除数据。界面标注需重新填写一次，用户重新保存该 API Key 后替换为本地文件密文，模型地址、名称和自定义处理配置继续保留。

普通工作台正文和处理结果仅在当前应用进程内存及系统剪贴板保留，不写入配置或日志；用户明确维护并保存的测试输入和预期输出属于测试配置，允许本地保存。关闭窗口隐藏到托盘，仍保留本次工作；完全退出释放应用内正文。

macOS 首次取文需要辅助功能授权。Tauri 和 Electron 的「权限检查」都调用同一个 Swift 取文程序的检测模式，按次读取系统授权，不触发复制、访问剪贴板或弹出授权窗口。取文也使用同一系统检查。拒绝授权时提示在辅助功能中添加当前安装的 CopyX，检测程序异常单独报错。Windows 普通权限软件无法可靠向管理员权限目标注入复制。JavaScript 上下文不暴露 Node、文件、网络或主进程桥接对象。

渲染进程禁用 Node 集成、启用隔离与沙箱，禁止外部导航、新窗口与渲染层网络访问。IPC 只接收主窗口主框架请求。

## 产品标识

产品名称为 CopyX，系统标题栏、托盘、安装包和快捷方式统一采用 CopyX，macOS 应用菜单提供「关于 CopyX」，由桌面宿主直接打开原生对话框。Tauri 使用运行中的应用版本与 Cargo 作者元数据，Electron 使用运行中的应用版本与包作者元数据。Tauri 在 macOS 使用透明原生标题栏显示窗口底色，和侧栏延续同一浅色底；通过 `hiddenTitle` 隐藏标题栏小字，保留窗口名称与系统按钮。React 在侧栏顶部以品牌图标和大字号 CopyX 展示品牌区，窄窗口适度缩小。React 负责主面板、导航及编辑器容器的圆角与视觉层次，选中项和主要操作使用偏蓝紫的品牌色。包名为 copyx。Electron 使用 `com.textworkbench.desktop` 和内部存储名称“文本工坊”。Tauri 使用 `com.textworkbench.desktop.tauri`，按本节前述迁移流程读取旧配置。模块职责与处理数据流不变。

应用主图采用白色圆角底座与蓝紫渐变的小熊头像。用户确认的原始位图保存在 `assets/copyx-master.png`，它是应用主图的唯一来源，替代旧的 `assets/copyx.svg`。在已安装项目 npm 依赖的 Mac 上执行 `swift scripts/create-icon.swift`：先生成 1024 像素 `assets/icon.png`，再调用本地 Tauri CLI 生成平台格式。Windows 的 `icon.ico` 从该 PNG 生成，主程序和 NSIS 安装、卸载程序共用该文件。macOS 的 `icon.icns` 从同一图稿提取蓝紫小熊头像，保留原稿的渐变与明暗，去掉原图底色和外缘阴影，再绘制到纯白圆角底板并保留约四分之一的横向留白，避免 macOS 26 将图标缩小后再套灰色底板。两种平台资源均从临时目录同步到 `src-tauri/icons/`。Electron Builder 在 macOS 使用同一适配版 ICNS，在 Windows 从主图 PNG 生成系统图标，窗口及 Windows 托盘也使用该 PNG。macOS 菜单栏使用 `assets/copyx-tray.svg` 的简化单色小熊头像，脚本同时生成 18 像素与 36 像素模板，由系统适配明暗外观；图标生成脚本同时从 macOS 适配图导出 `assets/copyx-brand.png`，裁掉画布外缘留白后供侧栏和网页 favicon 共用。运行时 PNG 随应用打包，主图及生成工具无需随包分发。图标生成脚本只在更新图标时运行，业务模块和运行时调用链路不变。

## 界面组织与状态边界

工作台空态提供直接输入和样例入口，完成后将复制结果设为主要操作。原文与结果编辑器分别提供可访问名称；复制与脚本执行仍经原有 Desktop 接口完成。

`App` 持有配置草稿、保存中状态、设置展开状态与模型连接结果。切换页面或处理条目时清除旧操作提示；工作台底部描述正文的临时保留，设置页描述配置与对话的本地持久化。模型连接结果与模型编号绑定，修改任一模型字段会清除旧连接结果，避免将旧测试成功状态用于新配置。

`SettingsActions` 仅负责共享操作栏布局，以属性和子元素组合保存按钮、状态和专项操作。`ScriptSettings` 继续持有测试报告和当前代码/用例对应关系，负责页签切换及测试/启用入口；代码编辑器和测试页保持挂载，切换页签不丢草稿。基本配置默认收起，新建或导入时自动展开，用户可以随时编辑名称、类型和快捷键。

保存范围继续沿用整体配置事务：保存草稿会保存全部待保存的名称、快捷键、模型等设置及脚本草稿，不替换生效脚本。启用此版本依次执行保存配置与原有激活校验，至少一例且全部通过，后台再次校验指纹；界面重排不绕过任何测试或权限检查。删除后仍有固定保存入口。

`ScriptGenerator` 以阶段提示、可展开上下文、独立滚动会话和固定输入区组织抽屉；确认动作紧邻已有方案。`RightDrawer` 通过可选内容样式支持对话布局，提示词历史继续使用原有滚动方式。持久化对话、Markdown 安全渲染、取消、覆盖确认以及模型调用协议不变。本次无新增后端接口、存储结构或部署依赖。

## 自定义指令的启用状态

`Scheme.disabled` 是独立于原有 `enabled`（快捷键兼容字段）的可选禁用标记，缺省为 `false`，旧配置无需迁移。Rust 使用 Serde 默认值，Electron 校验字段类型并在配置保存时持久化。禁用不改写脚本生效快照、测试集、提示词、模型绑定或对话；分享格式继续只携带可移植处理内容，不携带本机开关。

界面开关是独立的即时操作：使用现有 `config:get` 读取已保存配置，仅替换目标指令的 `disabled` 后调用 `config:save`，仍沿用原有配置事务与快捷键回滚。保存成功才更新开关和配置基线；编辑草稿仅合并同一指令的开关值，其他名称、脚本、测试或模型修改及未保存提示保持不变。失败保留原状态。前端保存互斥阻止重复切换或同时提交，未保存的新指令暂不能切换。工作台标记禁用选项并关闭执行按钮；两种桌面宿主在处理入口和快捷键取文目标解析处再次检查状态，阻止绕过界面执行。测试与脚本维护不受指令暂停限制。禁用脚本不参与键位注册；仅当存在可用的未禁用 AI 指令时注册共享键位。最近提示词绑定的指令被禁用时，不自动重放该指令；沿用目标失效提示流程，等待用户选择并成功执行有效指令。重新启用时走现有注册与冲突检查，失败按原配置事务回滚。

## 部署结构

Vite 将 React、Monaco、Markdown 和图标库编译成离线界面资源。完整的前端 npm 包仅用于构建，安装包包含产物 `dist`。主进程只随包分发 Acorn、QuickJS 核心和实际使用的同版本同步发布版 WASM。Electron 保留英文和简繁中文的运行时语言资源。用户无需安装 Node/Python。macOS Swift 辅助程序编译为 ARM64 并随应用资源分发；Windows 使用系统 Windows PowerShell 和 user32 原生接口。capture.ps1 作为 extraResources 实体文件发布，外部 PowerShell 通过 process.resourcesPath 下真实路径读取，不访问 ASAR 虚拟路径。分别提供 macOS UDBZ 压缩的 DMG 和 Windows NSIS 安装包。

第一版为内部预览构建，不代表已完成 Apple Developer ID 签名、公证或 Windows 代码签名。正式分发需要稳定签名身份，以维持应用身份和辅助功能权限的一致性。

内部预览包使用 ad-hoc 签名，其 designated requirement 绑定特定二进制版本。系统授权列表显示开启不等于当前进程已被系统认可；更新后可能需要用户移除旧的 CopyX 辅助功能条目并重新添加当前安装文件。0.1.2 已现场验证该恢复流程，正式发布需使用一致的证书签名。参考：[Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。
